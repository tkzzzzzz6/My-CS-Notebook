# 多模态 Pipeline

先以图片和文档为输入，搭建从数据接入到结果写回的可追踪流水线，再逐步扩展视频与音频。

## 一个最小闭环

```text
原始图片/文档
  → 样本 ID、内容哈希与元数据
  → 解析、解码、切片与预处理
  → Embedding 或视觉语言模型推理
  → 检索索引与结构化结果
  → Agent 工具与评测集
```

## 需要分别处理的工程问题

| 阶段 | 关注点 | 建议保留的测量 |
| --- | --- | --- |
| 数据接入 | Schema、数据版本、去重和损坏样本 | 有效样本率、读取吞吐 |
| 预处理 | 图片尺寸、文档切片、CPU 并行与内存 | 各阶段耗时、峰值内存 |
| 模型推理 | 输入大小、批大小、缓存和设备利用 | 样本吞吐、延迟、峰值显存 |
| 结果写回 | 可追踪样本 ID、部分失败和幂等重跑 | 写回吞吐、失败率、重复结果 |
| 质量验证 | 检索相关性、结构化输出和证据引用 | 固定样本集上的质量指标 |

先保留单机基线，出现明确的吞吐瓶颈后再加入分布式执行。[Ray Data 的 LLM 处理文档](https://docs.ray.io/en/latest/data/working-with-llms.html) 提供多阶段批推理的参考；[vLLM 基准工具](https://docs.vllm.ai/en/stable/benchmarking/cli/) 可用于观察多模态输入处理与服务表现。
