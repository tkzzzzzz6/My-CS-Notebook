# Agent 工程

本栏关注工具调用、执行状态、恢复和评测，并把 Agent 接入已有的模型服务与多模态数据链路。[贯穿项目](../Projects/index.md)。

## 建议的实现顺序

1. 用有限步骤的工作流实现检索、分析和回答，明确每一步的输入输出。
2. 给工具增加结构化结果、超时、错误分类与可重试条件。
3. 定义状态 Schema、Checkpoint 和恢复边界，验证重启后能否继续任务。
4. 再引入任务分支、上下文压缩、检索增强和记忆机制。
5. 用固定任务集检查质量、可靠性、时延和资源消耗。

## 每次实验要问的问题

| 主题 | 验证问题 |
| --- | --- |
| 工具契约 | 非法参数、空结果和部分失败如何表达？ |
| 状态与恢复 | 失败重放会不会重复执行有副作用的工具？ |
| 上下文 | 哪些信息需要持久化，哪些可以重新计算？ |
| 调度与预算 | 最大步数、超时和资源预算如何执行？ |
| 评测 | 任务成功率、证据引用、工具错误和时延如何测量？ |

[LangGraph 持久化文档](https://docs.langchain.com/oss/python/langgraph/persistence) 将 Checkpoint 与跨线程存储分别建模，可作为执行状态与长期信息管理的参考。框架接入后，要实际验证重启恢复、超时和重复执行等行为。
